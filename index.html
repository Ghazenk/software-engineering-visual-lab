01 / DATA FLOW DIAGRAMS03 / 20

What is a DFD?

Start with one simple path: patient details move from reception into the system and are stored.

A Data Flow Diagram (DFD) shows how data moves between people, processes and data stores.

It shows what data moves—not the order of screens, code or program instructions.
Remember · A DFD is a model of information movement, not a flowchart for control or program logic.
01 / DATA FLOW DIAGRAMS04 / 20

Four basic DFD symbols

Use these four symbols consistently in every following diagram.

External entity

A person or system outside the system boundary.

Example: Receptionist

Process

An activity that changes or uses data.

Example: Register patient

Data store

Information kept for later use.

Example: Patient records

Data flow

A labeled arrow showing what information moves.

Example: Test result

Remember · The meaning of the shape matters: rectangles = outside actors; rounded shapes = processes; stores = saved data; arrows = named data.
01 / DATA FLOW DIAGRAMS05 / 20

Context diagram

The context diagram is the highest-level view. It hides internal details.

Remember · Context diagram = one process for the entire system and its interactions with external entities. No internal data stores are drawn.
01 / DATA FLOW DIAGRAMS06 / 20

Level 0: inside the system

Level 0 DFD is often called the first decomposition diagram. Processes are numbered 1.0, 2.0, 3.0, and 4.0.

Remember · Level 0 breaks the whole system into its main numbered processes. Stores appear here because internal details are now visible.

02 / EXTREME PROGRAMMING09 / 20

What is Extreme Programming?

Define XP and explain short feedback cycles. XP is not the same as Scrum.

Extreme Programming (XP) is an Agile software development approach that helps teams build high-quality software in small steps while responding to change.

In XP, code is tested often, improved often and discussed with customers often.
PlanPick a small need.
BuildWrite code together.
TestCheck the result.
LearnGet feedback.

Then repeat the cycle with the next small improvement.

Remember · XP is about the day-to-day engineering work that helps small deliveries remain reliable.

The five XP values

Five values explain how an XP team thinks and works.

01

Communication

Share information and work together.

02

Simplicity

Build the simplest thing needed now.

03

Feedback

Learn quickly from tests and users.

04

Courage

Make necessary changes and fix problems.

05

Respect

Value teammates, customers and their work.

Remember · XP values guide decisions. XP practices are the concrete actions teams use to put them into effect.

Six important XP practices

Each practice is a practical habit that makes change safer.

01

Pair programming

Two developers work together on one task.

02

Test-driven development

Write a failing test before writing feature code.

03

Continuous integration

Integrate small changes and run checks frequently.

04

Refactoring

Improve code structure without changing its behavior.

05

Simple design

Avoid unnecessary complexity.

06

Small releases

Deliver useful changes frequently.

Remember · These are six commonly used XP practices, not the full historical list of XP practices.

03 / SCRUM14 / 20

What is Scrum?

Introduce Scrum as a framework, not just a task board or daily meeting.

Scrum is a lightweight framework that helps a team deliver value through short cycles called Sprints.

A Sprint is one month or less. Each Sprint should produce at least one usable Increment.
SPRINTOne month or less
PlanChoose goal.
WorkBuild & inspect.
ReviewGet feedback.
AdaptImprove next Sprint.
Remember · Scrum organizes collaboration and delivery; XP emphasizes engineering practices. A team may use both.
03 / SCRUM15 / 20

One Scrum Team, three accountabilities

Each accountability supports successful delivery in a different way.

01

Product Owner

Orders the Product Backlog to maximize product value.

02

Scrum Master

Helps the team and organization understand and use Scrum effectively.

03

Developers

Plan and create a usable, quality Increment during each Sprint.

Remember · These are the three Scrum accountabilities, all within one Scrum Team. “Developers” includes the people needed to build the product.
03 / SCRUM16 / 20

The five Scrum events

Clearly distinguish the five Scrum events (not five separate stages on a waterfall timeline).

The SprintContains all four other Scrum events; lasts one month or less.
01
Sprint Planning

Agree on why the Sprint matters and what to do.

02
Daily Scrum

Developers inspect progress and adapt their plan.

03
Sprint Review

Inspect the outcome with stakeholders and adapt.

04
Sprint Retrospective

Plan improvements to the team's way of working.

Remember · The Sprint is itself an event; Planning, Daily Scrum, Review and Retrospective happen within it.

04 / XP PRINCIPLES19 / 20

XP principles: people and value

Principles explain why XP practices make sense. These are principles 1–7.

01
Humanity

Build software in a way that respects people.

02
Economics

Spend time on work that creates value.

03
Mutual Benefit

Choose practices that help everyone involved.

04
Self-Similarity

Use helpful patterns at different scales.

05
Improvement

Make the product and process better each time.

06
Diversity

Use different skills and viewpoints.

07
Reflection

Stop regularly to learn from the work.

Remember · Source: Kent Beck and Cynthia Andres, Extreme Programming Explained, 2nd edition.
04 / XP PRINCIPLES20 / 20

XP principles: learning and quality

The remaining seven principles support safe progress, strong quality and ownership.

08
Flow

Keep useful work moving with fewer delays.

09
Opportunity

Treat problems as chances to improve.

10
Redundancy

Use overlapping checks to reduce serious errors.

11
Failure

Try small experiments and learn when they fail.

12
Quality

Do not trade away quality to move faster.

13
Baby Steps

Change one small, safe step at a time.

14
Accepted Responsibility

People take responsibility for work they accept.

Remember · DFD maps information · XP guides engineering · Scrum organizes collaborative delivery.
