01 / DATA FLOW DIAGRAMS

A picture of how data moves.

A Data Flow Diagram (DFD) shows where information comes from, how a system processes it, where it is stored, and where it goes.

It showsData movement and processing
It does not showScreen design or code instructions
One simple flow DFD example
Patient details move from the receptionist, through a process, into the patient data store.
LEARN THE SHAPES

Each DFD shape has one job.

01 / ENTITY

External entity

A person or outside system that sends or receives data.

Example: Receptionist
02 / PROCESS

Process

An action that changes or handles data.

Example: Register Patient

A place where data is kept for later use.

Example: D1 Patients

02 / EXTREME PROGRAMMING

Small steps.
Strong habits.

Extreme Programming (XP) is an Agile software development approach that uses frequent feedback, teamwork and disciplined coding practices.

XP / THE MINDSET

Good software starts with good habits.

01

Communication

Talk often so the team understands the work.

02

Simplicity

Build what is needed now; avoid unnecessary features.

03

Feedback

Test and listen early, then adjust.

04

Courage

Improve code and discuss problems openly.

05

Respect

Treat teammates and users with care.

Example: If receptionists cannot find a patient quickly, listen to their feedback and improve search before building more features.

XP does not wait until the whole application is finished to learn whether a feature works.
XP / HOW TEAMS WORK

Simple ideas, practiced consistently.

01

Pair programming

Two developers work together on the same code.

02

Test-driven development

Write a failing test before the code that passes it.

03

Continuous integration

Combine changes and run automated checks often.

04

Refactoring

Improve code structure without changing behavior.

05

Small releases

Deliver useful changes in small pieces.

06

Customer collaboration

Ask users about their needs throughout development.

03 / SCRUM FRAMEWORK

A shared goal.
One Sprint at a time.

Scrum is a lightweight framework where a small team delivers value in short periods called Sprints, usually lasting one month or less.

SCRUM / THREE ACCOUNTABILITIES

Three accountabilities. One team.

01

Product Owner

Chooses what is most valuable and orders the Product Backlog.

Example: Prioritizes patient search.
02

Scrum Master

Helps everyone understand and use Scrum effectively.

Example: Removes obstacles to team progress.
03

Developers

Plan, build, test and deliver a usable Increment.

Example: Implement and test registration.

04 / XP PRINCIPLES

The ideas behind the habits.

01

Humanity

Remember the people doing the work.

02

Economics

Choose work that gives real value.

03

Mutual benefit

Try to help customers and teammates together.

04

Self-similarity

Use a good solution pattern at different scales.

05

Improvement

Keep making the work a little better.

06

Diversity

Different skills and viewpoints improve decisions.

07

Reflection

Pause to learn from what happened.

04 / XP PRINCIPLES

Keep learning. Keep improving.

08

Flow

09

Opportunity

10

Redundancy

11
