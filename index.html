01 / DFD FOUNDATION

What exactly is a DFD?

DFD = Data Flow Diagram.
A picture of how information enters a system, gets transformed, is stored, and leaves.

INPUT

Patient details arrive.

PROCESS

The system checks and registers them.

STORE / OUTPUT

Data is saved; a patient ID is returned.

Information moves on labeled arrows — not people or clicks.
DFD does show: data movement and transformations. DFD does not show: detailed code, timing, or step-by-step program control.

01 / DFD AVOID THESE MISTAKES

A good DFD follows simple rules.

✕

Entity → Store?

Patient→Database

Not directly. Use a process to validate or transform the data first.

✕

Unlabeled arrow?

Process A→Process B

Not enough. Name the information, e.g. “test request” or “lab result”.

✓

Balanced levels?

Level 0⇄Level 1

Yes. A decomposed process must preserve the same external input / output flows.

Exam tip: A DFD is not an ER diagram (data structure), and it is not a flowchart (control sequence).

02 / XP DEFINITION

XP is not about typing faster.

Extreme Programming (XP) is an agile software development approach that delivers useful software in small increments with frequent feedback and strong technical practices.

“If testing is good, test often. If feedback is good, get it early. If code review is good, collaborate continuously.”Plain-language interpretation of the XP approach
WORKING
SOFTWARE
ListenBuildTestLearn
Example: Lab staff request a new “pending / completed” status. Instead of waiting months, the team plans a small change, tests it, releases it, and learns.

02 / XP REAL-WORLD JUDGMENT
Why teams choose XP — and when it’s hard.
↗ WHAT XP HELPS WITH
Changing requirements
Small iterations welcome updates from lab staff.
Quality and reliability
Frequent tests catch issues earlier.
Knowledge sharing
Pairing and collective ownership reduce silos.
! WHAT XP NEEDS
Customer availability
Feedback becomes harder if users cannot participate.
Strong engineering discipline
Testing and refactoring take practice, not shortcuts.
Team buy-in
Collaboration and role switching can feel unfamiliar.
Key idea: XP can support rapid change because it protects quality while the team works in small increments.

    


    
    

    

      
03 / SCRUM DEFINITION
Scrum is how a team learns while delivering.
Scrum is a lightweight framework for a small team to deliver valuable work in short, fixed-length cycles called Sprints.
TRANSPARENCY
Everyone can see the current work and goals.
INSPECTION
Check the product and team progress regularly.
ADAPTATION
Change the plan based on what was learned.
SPRINT≤ 1 month
PlanBuildInspectAdapt
Example: In a two-week Sprint, the MediLab team creates an end-to-end report-status feature that staff can actually use.

03 / SCRUM 5 OFFICIAL EVENTS
A Sprint contains four other events.
THE SPRINTONE MONTH OR LESS
01
Sprint Planning
Why, what, and how will we deliver?
02
Daily Scrum
15 minutes to inspect progress and adapt the plan.
03
Sprint Review
Inspect the product outcome with stakeholders.
04
Retrospective

↻ NEXT SPRINT: apply learning and keep delivering value
Important: The Sprint itself is the fifth event; the Daily Scrum is not a report to a manager.
